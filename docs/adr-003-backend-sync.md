# ADR-003 — Backend, Authentication & Multi-Device Synchronization

**الحالة:** معتمد · **يبني على:** ADR-001, ADR-002 · **يحل:** قيد الجهاز الواحد الموثّق منذ v0.13

## السياق
النموذج الأولي (localStorage) اكتمل. كل متصفح يملك بياناته: المدرب لا يرى متدربًا على جهاز آخر، المدير لا يرى تحليلات المنظمة، الأدمن لا يشغّل مؤسسة حقيقية. Phase 7 يحوّل المنصة لمتعددة المستخدمين — **بتغيير البنية التحتية فقط، صفر تغيير في قواعد العمل.**

## المبدأ الحاكم: استبدال المحوّلات فقط
الأربع عقود (`ProgressBackend`, `IdentityBackend`, `TrainingBackend`, `AuthProvider`) اتصمّمت من ADR-001/002 كنقاط استبدال. Phase 7 = **تنفيذات REST لنفس العقود**. الطبقات فوقها (domain, reducers, analytics, UI) **لا تعرف ولا تتغير**. ده مش وعد — ده اختبار: لو أي شاشة احتاجت تعديل، يبقى العقد كان ناقص.

## 1) المصادقة (Authentication)
- **`AuthProvider` يبقى كما هو** (`getSession() → Session | null`). نستبدل `LocalDevAuthProvider` بـ`OidcAuthProvider`.
- **التدفق:** OIDC (Authorization Code + PKCE) → المزوّد يرجّع JWT (access قصير + refresh). الـclaims تحمل `userId` والدور.
- **الأسرار أبدًا في المتصفح:** الـrefresh token في httpOnly cookie؛ الـaccess في الذاكرة فقط. لا كلمات مرور تُخزّن أو تُرى في العميل — إعادة التعيين تدفّق backend كامل (بريد + توكن مؤقت).
- **`can()` لا يتغير:** الصلاحيات تُشتق من دور المستخدم كالمعتاد؛ الـJWT يحمل الدور، لا الصلاحيات الخام (الأدوار تتغير كبيانات، فبثّ الصلاحيات في التوكن يجمّدها).

## 2) التفويض (Authorization) — دفاع بعمق
العميل يفحص `can()` لإخفاء ما لا يُسمح (UX)، **والخادم يفحص نفس الصلاحيات على كل mutation** (الأمان). **العميل لا يُوثَق أبدًا** — RBAC نفسه (كتالوج الصلاحيات + الأدوار) يعيش على الخادم كمصدر حقيقة، والعميل نسخة للعرض.

## 3) الخادم وثبات الأحداث
- **نفس نموذج ADR-001 على الخادم:** جداول append-only للأحداث الأربعة (progress/training/identity/audit)، وsnapshots مشتقة. الـreducers **نفسها** (كود domain مشترك) — الخادم والعميل يشتقّان بنفس الدوال النقية، فمستحيل يختلفوا.
- **API:** REST بحدود واضحة — `POST /events/{log}` (إلحاق)، `GET /events/{log}?since=cursor` (مزامنة تزايدية)، `GET /snapshot/{log}`. لا منطق عمل في الـcontrollers — بس تحقّق صلاحية + إلحاق + اشتقاق.

## 4) المزامنة (Synchronization)
- **تزايدية بالـcursor:** كل سجل له cursor (آخر حدث متزامن). العميل يبعت الجديد، يسحب من الـcursor. لا نقل كامل بعد أول مرة.
- **الأحداث append-only = مزامنة بسيطة:** إرسال أحداث جديدة، لا تعديل. الـsnapshot يُشتق محليًا فورًا (optimistic) ويُصحّح من الخادم.

## 5) دون اتصال (Offline)
- **cache محلي** (نفس الـlocalStorage adapter كطبقة cache).
- **طابور mutations:** الأحداث تُلحق محليًا + تُوضع في طابور؛ retry تلقائي عند العودة.
- **UI متفائل:** الـreducer النقي يطبّق الحدث فورًا؛ لو الخادم رفض (صلاحية)، نتراجع بإعادة اشتقاق snapshot من أحداث الخادم.

## 6) حل التعارض (Conflict Resolution)
- **الأحداث تراكمية بطبيعتها** — نادرًا تتعارض (مش تحديث حقل، بل إلحاق واقعة). ترتيب زمني بـ`at` + معرّف حدث.
- **الحالات الحسّاسة (اعتماد المدرب):** الـreducer محسوم بالفعل — «الاعتماد لا يتراجع بإعادة الإرسال» (مختبر في Phase 4). آخر كاتب لا يفوز عشوائيًا؛ الدلالة في الـreducer تحكم.
- **الهوية (تعارض تعيين):** آخر حدث بـ`at` أحدث يفوز، والتاريخ كامل في السجل للمراجعة.

## 7) الأمان
تحقّق صلاحية على كل mutation · تحقّق مدخلات على الخادم (لا يُكرَّر منطق — schema مشتق من أنواع domain) · **نزاهة التدقيق:** سجل التدقيق append-only على الخادم بلا حذف/تعديل (WORM)، توقيع تسلسلي اختياري · rate limiting · CSRF (SameSite + توكن) · تشفير أثناء النقل (TLS) والسكون (DB).

## 8) الأداء والتوسع (10 آلاف مستخدم · ملايين أحداث)
snapshots مشتقة مخزّنة على الخادم (قراءة O(1)) · مزامنة تزايدية (نقل O(الجديد)) · pagination للتدقيق · الـselectors memoized (موجود) · lazy loading للتحليلات.

## 9) النشر والتعافي
نشر بيئتين (staging/prod) · نسخ احتياطي: **سجل الأحداث append-only = نسخة احتياطية بطبيعته** (replay يعيد بناء أي snapshot) · تعافٍ من كارثة: استعادة السجل → إعادة اشتقاق كل الـsnapshots بالـreducers. RPO منخفض (نسخ دورية للسجل)، RTO = زمن الـreplay.

## العواقب
- **تنفيذ، لا إعادة كتابة:** الطبقات فوق العقود ثابتة.
- **الـreducers المشتركة** بين العميل والخادم تمنع اختلاف الاشتقاق.
- **الحدود المعلنة تُرفع:** المزامنة عبر الأجهزة، تحليلات المنظمة، التشغيل الحقيقي — كلها تعمل.

## نطاق هذا الإصدار (v0.20)
البنية التحتية الحقيقية (خادم منشور) خارج بيئة العميل ده. **ما يُسلّم الآن:** عقود API نوعية + `RemoteBackend` adapters (fetch) خلف flag + طبقة مزامنة/طابور + `OidcAuthProvider` seam + اختبارات تكامل تحاكي الخادم (mock transport) تثبت أن الطبقات العليا لا تتغير. **التبديل production = تفعيل flag + عنوان خادم.**
