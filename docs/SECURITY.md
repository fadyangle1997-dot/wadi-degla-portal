# الأمان — الوضع الحالي والمخطط

> المبدأ الحاكم: **العميل مش موثوق أبدًا، والخادم هو مصدر الحقيقة.**
> النسخة 7.28.0 نموذج أولي شغّال في المتصفح بس. الجدول تحت بيفرّق بين **المنفّذ فعلًا** و**المخطط للخادم**، عشان محدش يعتمد على حماية لسه متعملتش.

## المنفّذ في النموذج الحالي
| البند | الحالة |
|---|---|
| كلمات السر التجريبية | SHA-256 مملّحة (`salt:username:password`). مفيش كلمة سر مقروءة في الحزمة، والـCI بيفحص `dist/`. |
| الأسماء | كل الحسابات التجريبية بأسماء وهمية. |
| Content-Security-Policy | `index.html` (meta)، و`vercel.json` و`public/_headers` فيهم الـheaders كاملة: CSP مع `frame-ancestors 'none'`، وHSTS، و`nosniff`، و`X-Frame-Options`، و`Referrer-Policy`، و`Permissions-Policy`، و`COOP`. |
| XSS | React بيعمل escape، ومفيش `dangerouslySetInnerHTML` ولا `eval`. اختبارات Playwright بتفشل لو حصلت أي مخالفة CSP. |
| الصلاحيات في الواجهة | الصلاحيات بـRBAC عن طريق `can()`، ونطاق كل مستخدم من `scopeOf()`. حماية الشاشات بتقفل تلقائيًا لو حصل أي خطأ، ومسار تقرير الجاهزية بيتحقق من نطاق الـid نفسه. |
| نسب كل فعل لصاحبه | أي كتابة في الهوية أو التدريب من غير مستخدم مسجّل بترفض، ومفيش نسب افتراضي لمسؤول النظام. |
| فصل بيانات المستخدمين | تقدّم كل مستخدم متخزّن لوحده (`wda.progress.v3:<id>`). |
| التخزين حد ثقة | أي بيانات شكلها غلط في أي مخزن بتتعامل كأنها مش موجودة. |
| التبعيات | الـCI بيشغّل `npm audit --audit-level=high` (النتيجة الحالية 0)، وDependabot بيفتح PR أسبوعي للتحديثات. |

## الحدود المعروفة (مقبولة في نموذج أولي، **ومرفوضة في الإنتاج**)
- **الدخول بيتم في المتصفح.** أي حد عنده DevTools يقدر يعدّل الجلسة المتخزّنة ويدخل بأي دور. ده باب للعرض، مش مصادقة.
- **البيانات في `localStorage`.** مش مشفّرة، ومحدش غير المتصفح بيتحكم فيها.
- **ممنوع إدخال بيانات موظفين أو أعضاء حقيقية** في النسخة دي.

## المخطط مع الخادم (ADR-005، المراحل 2–9)
- **المصادقة:** OIDC (Authorization Code + PKCE)، والـaccess token في الذاكرة، والـrefresh في httpOnly cookie. ومش هيبقى فيه أي كلمة سر في العميل.
- **التفويض:** الخادم بيعيد فحص `can()` و`scopeOf()` على كل mutation، والـ`actor_id` بيتاخد من التوكن مش من الطلب.
- **التدقيق:** سجل append-only بصلاحيات INSERT/SELECT بس (WORM)، و`seq` بيكشف أي فجوة.
- **التشغيل:** rate limiting، وCSRF (SameSite + توكن)، وتشفير أثناء النقل والتخزين، وإخفاء أي بيانات حساسة من الـlogs، واختبار اختراق مستقل قبل ما تدخل أي بيانات حقيقية.
