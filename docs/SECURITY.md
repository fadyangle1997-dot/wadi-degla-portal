# تدقيق الأمان — v1.0

> المبدأ الحاكم: **العميل لا يُوثَق أبدًا. الخادم مصدر الحقيقة.**

## المصادقة
OIDC (Authorization Code + PKCE). access token في الذاكرة فقط؛ refresh في httpOnly cookie. **لا كلمات مرور تُخزّن أو تُرى في العميل.** إعادة التعيين تدفّق backend كامل (`PASSWORD_RESET_REQUESTED` حدث تدقيق فقط في العميل).

## التفويض (دفاع بعمق)
- **العميل:** `can()` يخفي ما لا يُسمح — **UX فقط، ليس أمانًا**.
- **الخادم:** يفحص نفس الصلاحية على **كل** mutation. RBAC (كتالوج + أدوار) مصدره الخادم.
- **منع تصعيد الصلاحية:** التوكن يحمل الدور لا الصلاحيات الخام؛ الأدوار بيانات على الخادم، فتعديلها لا يتطلب إعادة إصدار توكن ولا يُجمّد الصلاحيات.

## سطح الهجوم في العميل
- **XSS:** React يهرّب افتراضيًا؛ لا `dangerouslySetInnerHTML` في الكود. CSP موصى بها عند النشر.
- **CSRF:** SameSite cookies + توكن (عند الخادم).
- **تحقّق المدخلات:** يُكرّر على الخادم (schema مشتق من أنواع domain — لا منطق مزدوج).
- **الأسرار:** لا أسرار في الحزمة؛ عناوين الخادم عبر متغيرات بيئة وقت النشر.

## نزاهة التدقيق
سجل append-only، لا حذف/تعديل. تسلسل `seq` يكشف أي فجوة. توقيع تسلسلي اختياري.

## التبعيات
حزمة صغيرة (React, motion, lucide). فحص `npm audit` في الـCI موصى به.

## المتبقّي قبل الإنتاج (حواجز)
نشر خادم فعلي بالفحوصات دي · rate limiting · security headers/CSP · اختبار اختراق مستقل.
