# دليل التشغيل (Runbook) — أكاديمية عمليات العضويات

> دليل الفريق التشغيلي: النشر، المراقبة، النسخ الاحتياطي، والاستجابة للحوادث.

## 1) البنية باختصار
واجهة React (Vite) + 4 سجلات أحداث append-only (progress/training/identity/audit). Domain نقي مشترك بين العميل والخادم. التبديل local↔remote بـflag واحد (`BACKEND_CONFIG`). 3 قرارات معمارية موثّقة (ADR-001/002/003).

## 2) النشر (Deployment)
- **بناء:** `npm ci && npm run build` → مخرجات ثابتة في `dist/`.
- **البوابة:** الـCI (`.github/workflows/ci.yml`) بيشغّل قبل أي دمج: lint، وفحص الأنواع (الواجهة والخادم والأدوات)، واختبارات Vitest بحد أدنى للتغطية، والبناء، وحد أقصى لأول تحميل، وفحص إن مفيش أي بيانات دخول في `dist/`، و`npm audit`، واختبارات Playwright (الأدوار وaxe وCSP والترجمة).
- **الاستضافة الثابتة:** `vercel.json` (Vercel) و`public/_headers` (Netlify / Cloudflare Pages) فيهم headers الأمان والـcache.
- **الإنتاج:** `BACKEND_CONFIG.mode='remote'` + `apiBaseUrl`. صفر تغيير كود أعلى المحوّلات.
- **الفصل البيئي:** staging (بيانات وهمية) → production. rollback = إعادة نشر البناء السابق (ثابت، بلا هجرة).

## 3) المراقبة (Monitoring) — ما يجب رصده
| المقياس | التنبيه |
|---|---|
| توفر الـAPI (`/health`) | فشل > 1 دقيقة |
| فشل المزامنة (`SyncEngine` retries) | طابور معلّق > N |
| فشل المصادقة (OIDC) | ارتفاع مفاجئ |
| فشل التخزين (`healthy()=false`) | أي حدوث |
| نزاهة التدقيق | أي فجوة تسلسل seq |

## 4) قابلية الرصد (Observability)
- **أخطاء التطبيق:** `ErrorBoundary` يسجّل مركزيًا (يصبح تقرير remote في الإنتاج).
- **بنيويًا:** كل حدث يحمل actor + timestamp — سجل الأحداث نفسه هو سجل التدقيق.
- **مقاييس تشغيلية:** محرك الصحة (`detectOperationalIssues`) قابل للجدولة كتقرير دوري.

## 5) النسخ الاحتياطي والتعافي (Backup & DR)
- **الاستراتيجية:** سجل الأحداث append-only = **نسخة احتياطية بطبيعته**. نسخ دورية للسجلات الأربعة.
- **RPO:** = دورية النسخ (موصى: كل ساعة). **RTO:** = زمن إعادة اشتقاق الـsnapshots بالـreducers (replay).
- **الاستعادة:** استرجاع السجل → `reduce()` على كل حدث → snapshots كاملة. مثبت بنفس الدوال النقية المختبرة.
- **حفظ التدقيق:** سجل `identity.audit` WORM — لا حذف/تعديل، احتفاظ طويل للامتثال.

## 6) قاعدة البيانات (عند النشر)
جداول append-only للأحداث (فهرس على `at` + `seq` للمزامنة التزايدية) · قيود مرجعية على الإسنادات · الهجرة = إضافة أنواع أحداث (الأحداث القديمة تبقى صالحة، الـreducer يتعامل معها) · الأرشفة بالحالة لا الحذف.

## 7) حدود النظام المعروفة (v1.0)
- المزامنة تعمل عبر الأجهزة عند تفعيل الخادم (البنية جاهزة، النشر خارج نطاق كود العميل).
- الأفعال الجماعية: المنطق جاهز ومختبر؛ ربط selection في الواجهة = بند UI مؤجّل.
- Decision Lab: مصمّم (`docs/decision-lab.md`)، غير منفّذ.
