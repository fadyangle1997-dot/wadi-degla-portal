# Decision Lab — التصميم المعماري (Task 5 · تصميم فقط، التنفيذ لاحقًا)

## المكان في الرحلة
`Unit Exam ← Decision Lab ← Boss Battle` — طبقة بين إثبات الفهم (الامتحان) وتطبيق القصة الكاملة (الـBoss).

## الفكرة
الامتحان بيقيس «فاهم القاعدة؟»، والـBoss بيقيس «تشتغل يوم كامل؟». الـDecision Lab بيقيس الحلقة المفقودة: **«تاخد القرار الصح تحت تنويع لا نهائي؟»** — مواقف ذرّية قصيرة، كل واحد قرار واحد، **مولّدة ديناميكيًا** فمفيش حفظ إجابات.

## منع الحفظ (الآلية الجوهرية)
كل عنصر = **قالب مُعامل (parameterized template)** مش سؤال ثابت:
```ts
interface DecisionTemplate {
  id: string;
  skill: string;                 // المهارة اللي بيقيسها (من كتالوج SKILLS)
  ruleRef: RuleRef;              // القاعدة الحاكمة
  generate(seed: number): {      // توليد حتمي من seed
    prompt: string;              // «ابن مولود {2013} اتضاف {2026}…»
    options: QuizOption[];
    explanation: string;
  };
}
```
- المدخلات بتتسحب عشوائيًا **من نطاقات معتمدة** (سنة ميلاد 2005-2015، شهر تجديد 4-12…).
- **الإجابة الصحيحة بتتحسب من محرك القواعد نفسه** (`childJoiningPenalty(...)`) — مش مكتوبة يدويًا، فمستحيل تدرِفت عن القاعدة، والمشتتات = أخطاء محسوبة (نسيان استبعاد الضريبة، شريحة غلط).
- نفس القالب = آلاف الأسئلة المختلفة. الحفظ بلا قيمة؛ الفهم هو الطريق الوحيد.

## البيانات المولّدة (وليه المدرب والمدير هيحبوها)
كل قرار بيصدر حدث `DECISION_LAB_COMPLETED` (محجوز في backend.ts) + تفاصيل:
`{ templateId, skill, ruleRef, correct, msTaken }`
- **للمدرب:** «أحمد غلط 4 مرات في قوالب renewal.withinYear» → إشارة تدخّل محددة، مش «أحمد ضعيف».
- **للمدير:** تجميع فوق المهارات: «مهارة الحسابات المالية 63% على مستوى الدفعة» → قرار إعادة تصميم درس، مش انطباع.
- ده اللي بيحقق مطلب «قياس Skills مش وحدات» — الـLab هو مصدر بيانات المهارات الأدق.

## الفرق عن الـBoss Battle
| | Decision Lab | Boss Battle |
|---|---|---|
| الشكل | قرارات ذرّية سريعة | قصة عميل/يوم كامل |
| المحتوى | مولّد ديناميكيًا | مكتوب بعناية (ثابت) |
| يقيس | إتقان مهارة تحت تنويع | تركيب المهارات مع بعض |
| التكرار | لانهائي بلا حفظ | مرّة مشهودة |
